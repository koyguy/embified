WhatsApp Cloud API setup

Use this when you will not run an unofficial linked-device client. Meta hosts the phone number; Embified only receives HTTPS webhooks into your local vault.

Meta requires a public HTTPS callback. A raw Always Free IP on port 80 is not enough. Put Cloudflare Tunnel (or any reverse proxy with a cert) in front of Embified, then paste that origin into the inbox Cloud API form.

1 · Meta developer app

  1. Create an app at developers.facebook.com and add the WhatsApp product.
  2. Attach a Cloud API phone number (Business Platform — not a normal “linked devices” session).
  3. Copy the access token and the Phone number ID.
  4. Invent a verify token, or let Embified generate one when you switch to Cloud API.

2 · HTTPS in front of your vault

On the vault VM:

sudo bash /opt/embified/scripts/home-box/install-cloudflared.sh
# (or scripts/cloud-api-https/ on an Oracle vault)
sudo bash /opt/embified/scripts/cloud-api-https/start-quick-tunnel.sh

Quick tunnels print a https://*.trycloudflare.com URL (changes if the tunnel restarts). For a stable hostname, create a named Cloudflare Tunnel pointed at http://127.0.0.1:80.

3 · Connect Embified

  1. Open the inbox, choose Official Cloud API.
  2. Paste access token + phone number ID.
  3. Paste the tunnel origin (no path) into Public HTTPS origin.
  4. Copy the shown verify token and full callback URL into Meta → WhatsApp → Configuration.
  5. Subscribe to messages. For official groups also subscribe to the group fields Meta lists for your app.

Limits (honest)

  • 1:1 customer chats work on a standard Cloud API number.
  • Official group archive needs an Official Business Account and Groups API eligibility.
  • Baileys remains available for regular app numbers already in groups — with unofficial-client risk.
